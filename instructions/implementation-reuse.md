# 既存機能・UIの調査と再利用

このゲームの機能・UIの追加や修正について、案を提示するとき、設計するとき、または実装するときに適用する。案の提示だけの場合も、作業を始める前にこの方針を読む。

- 提案・設計・実装を始める前に、同じ用途や近い振る舞いの機能・UIがないか調べる。画面の表示名、操作内容、関連するコード名を手掛かりに、実装と既存の仕様を検索する。
- 見つかった候補は、該当箇所と利用している共通部品・処理を読んで確認する。名前や検索結果だけで、再利用できると判断しない。
- 要件に合う既存の型・部品・処理・定義・スタイルを優先して使う。調整が必要な場合は、既存の利用箇所への影響を確認し、今回の変更に必要な範囲で拡張・共通化する。
- 再利用するときは、表示項目、初期設定、操作方法も確認する。見た目や説明文はそのまま継承せず、このゲームの試作方針と今回の要件に合わせる。既存の機能や操作を変更する場合は、必要性と理由を簡潔に示す。
- 別プロジェクトを参照するときは、参照元のルート `AGENTS.md` と、その作業に該当する指示・仕様を先に読む。参照できない場合はその制約を示し、未確認の部品が使えるとは断定しない。
- 別プロジェクトから採用するコード・仕様は、このリポジトリ内に配置し、必要な依存関係を確認する。別プロジェクトのローカルパスに実行・ビルド・仕様参照を依存させない。参照元の変更は、その変更も依頼された場合に行う。
- 同じ役割の実装を作り直さない。再利用のために、依頼と無関係な一括移植や大規模な改修を行わない。
- 提案・設計では、参考にした実装、再利用する部分、追加・変更が必要な部分を簡潔に示す。実装後も、実際に再利用したものと変更点を伝える。
- 適切な候補が見つからない場合や、既存実装が要件に合わない場合は、その旨と新規作成が必要な理由を簡潔に示す。
