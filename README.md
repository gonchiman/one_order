# ONE ORDER

TypeScript・Phaser・Viteを使う、ONE ORDERの開発用リポジトリです。
1台のPCで両プレイヤーを手動操作し、配置編集から勝敗・再戦まで試せる実験盤を含みます。以下のルールと数値は実験用の仮ルールです。

## 必要な環境

- Node.js 24.x
- npm 11以上（Node.jsに同梱）

Node.jsのバージョン管理ツールを使う場合は、`.nvmrc`の指定を利用できます。

## 起動

リポジトリを取得し、プロジェクトのフォルダで実行します。

```sh
npm ci
npm run dev
```

ブラウザで <http://127.0.0.1:5173> を開きます。
白地の盤面と「配置編集」「対戦開始」の操作が表示されれば起動成功です。
ソースを保存するとViteが変更を反映します。

開発サーバーはターミナルで `Ctrl+C` を押すと停止します。
5173番ポートが使用中の場合は、`npm run dev -- --port 5174` などで変更できます。

## コマンド

| コマンド | 用途 |
| --- | --- |
| `npm run dev` | 開発サーバーを起動 |
| `npm run typecheck` | TypeScriptの型をチェック |
| `npm run build` | 型チェック後、`dist/`に本番用ファイルを生成 |
| `npm run preview` | 本番用ファイルを <http://127.0.0.1:4173> で確認 |
| `npm test` | Vitestを1回実行 |
| `npm run test:watch` | Vitestを監視モードで実行 |

プレビューの前に `npm run build` を実行してください。
`npm test`は、兵科・移動力・優先度・壁の迂回・移動先の競合・初期指示・指示制限・同時攻撃・勝敗・再戦と履歴の復元を検証します。

## 実験盤の使い方

1. 「配置編集」の「マップ」タブで幅・高さ（3〜12）を指定し、「新しいマップを作成」します。ユニットの配置は初期状態に戻ります。
2. 「ユニット」タブの「配置・初期指示」で選択・移動／追加／削除を選び、盤面のマスを操作します。追加時は「追加する陣営」「追加する兵科」を選びます。移動するユニットは、盤上・盤面下の一覧・「選択中のユニット」で選びます。
3. 選択したユニットの陣営・兵科・最大HP・攻撃力・射程・移動力・移動優先度を変更できます。最大HPの変更は現在HPも回復します。兵科を変えると、その兵科の初期値へ全能力を戻します。「移動力を初期値に戻す」は移動力だけを戻します。
4. 「マップ」タブで壁・平地・P1陣地・P2陣地を座標指定、または「盤面で配置」で置けます。勝敗の有無、初回優先権、上限ターンも変更できます。
5. 「対戦開始」を押した直後は「初期指示（無制限）」になります。最初にターンを進めるまで、P1・P2の全ユニットへ何度でも目的地を設定・変更・解除できます。空きマスを押すか座標を入力して設定します。「目的地を指定」を押してからマスを選ぶと、ユニットがいるマスにも指示できます。
6. 配置編集の「初期指示」から先に目的地を用意することもできます。対戦開始後もその指示を引き継ぎ、最初のターンが進むまでは自由に変更できます。「選択・移動」に戻すと配置を編集できます。
7. 「1ターン進める」で全員が同時に移動し、その後に射程内の敵へ同時攻撃します。最初の実行直前の配置・初期指示・能力・HP・地形・ルールを開始設定として記録し、以後の指示は各陣営1ターン1体までになります。HPは盤上・一覧・選択中のユニットで確認でき、盤面下に直前の戦闘結果が表示されます。狭い盤面では盤上のHP表示を省きます。
8. 「1ターン戻す」でターン直前の配置・目的地・能力・HP・指示済みのユニット・行動と戦闘の表示を復元します。撃破されたユニットも戻ります。「開始配置に戻す」で初期指示を含む同じ設定から試し直せます。
9. 勝敗がつくと結果を表示し、それ以上の指示・ターン進行を停止します。「同じ配置で再戦」で開始設定へ戻ります。試合終了後も「1ターン戻す」で結果を取り消して検証できます。

X・Yの数値入力と操作ボタンでも、盤面上の操作と同じことができます。座標は左上を `(1, 1)` とします。
盤面下の「全指示をリセット」は、両陣営すべての目的地と使用済み指示枠を空にする実験用の操作です。位置・HP・ターン数・地形・履歴・保存済みの開始設定は保持します。配置編集中・初期指示中・対戦中に使え、試合終了後は使えません。通常ターンでリセット後に出せる新しい指示は、各陣営1体までです。
タブの切り替えで配置や入力中の内容は変更されません。タブは左右矢印・Home・Endキーでも切り替えられます。
配置編集へ戻ると、現在位置を残して指示・ターン数・履歴をリセットします。
開始配置と履歴は画面を開いている間だけ保持し、ページを再読み込みすると初期状態に戻ります。

## 実験用の仮ルール

- 初期盤面は9×9で、P1・P2それぞれに歩兵・騎兵・弓兵を1体ずつ配置します。盤上の「歩」「騎」「弓」が兵科を表し、P1は青い丸、P2は赤い四角です。各陣地を上下端に配置し、幅・高さがともに7以上なら対称の壁を配置します。
- 対戦開始直後、最初のターンを進めるまで（表示はターン0）は、両陣営とも全ユニットへ回数制限なしで初期指示を設定・変更・解除できます。配置編集中にも事前設定できます。1ターン進めた後は、各陣営に1ターン1体ずつ指示できます。同じユニットの指示はターンを進めるまで修正でき、指示解除も1体分として数えます。「1ターン戻す」でターン0に戻った場合も初期指示を修正できます。敵の自動移動はありません。
- 指示は変更されるまで継続します。上下左右の最短経路を探し、停止しているユニットを迂回して目的地を目指します。同じ長さの経路では、目的地へ横方向に近づく経路を優先します。
- 移動力の仮の初期値は歩兵1・騎兵2・弓兵1マスです。配置編集ではユニットごとに1〜12マスの整数へ変更できます。兵科を変更すると、その兵科の初期移動力になります。
- 1マスずつ全員の移動候補を同時に判定します。同じマスへの競合では移動優先度が高い1体が進みます。同値ならそのターンの優先プレイヤーを優先します。優先権はターン中固定し、次のターンで交代します。同じ陣営内の同値はID順をターンごとに持ち回りにします。
- 全兵科の移動優先度は仮に1から開始し、各ユニットで1〜99に変更できます。競合で譲ったユニット、停止中のユニットに遮られた移動、入れ替えや循環移動は、そのターンの残りの移動を停止します。
- 壁は通行不可で、ユニット・陣地・設定済みの目的地と同じマスには置けません。壁や他のユニットの迂回には既存の最短経路探索を使います。壁による射線・射程・ダメージの変化はありません。
- 1マス進むたびに占有状況から経路を探し直します。移動力を使い切ったユニットも迂回の対象です。前のユニットが空きマスへ進む場合は、後続も同時に進めます。
- 通れる経路がなければそのターンは待機し、目的地の指示を保持します。通路が空けば次のターンに再び進みます。目的地にユニットがいる場合は接近して待機し、マスが空くまで進入しません。
- 移動後、各ユニットは射程内の敵1体を自動で攻撃します。距離は上下左右のマス数の合計で計算します。最も近い敵を選び、同距離なら識別番号の小さい敵（A、B、…の順）を選びます。移動途中の攻撃はありません。
- 攻撃力分のダメージを全員同時に与え、HPが0になったユニットを除去します。同じターンに撃破されるユニットも攻撃します。反撃という別処理や、味方への攻撃はありません。
- 戦闘終了後、生存ユニットが相手陣地にいるか、相手ユニットが全滅していれば勝利です。自陣地への到達では勝利しません。両陣営が同時に条件を満たす場合（双方全滅を含む）は引き分けです。
- 既定では50ターンで決着がつかなければ引き分けです。最終ターンでも到達・全滅による勝敗を先に判定します。上限は1〜999で変更できます。「勝敗なし」では終了判定を行わず実験を続けられます。
- HP・攻撃力は1〜99、射程は1〜12マスへ変更できます。選択中のユニットの移動範囲を淡い灰青の塗り、現在地からの攻撃射程を細い枠で重ねて表示します。選択解除で両方消えます。
- 移動範囲は、現在の配置で壁と他ユニットを避け、上下左右の最短経路が移動力以内となる空きマスです。他ユニットの指示や移動優先度は予測に含めず、同時移動で進路が空いたり競合したりすると結果は変わります。範囲外や敵のいるマスも、従来どおり目的地に指定できます。
- 兵科・陣営・初期能力は `src/core/unitTypes.ts`、陣営ごとの指示上限は `src/core/board.ts` の `DEFAULT_RULES` で管理しています。

| 兵科 | 最大HP | 攻撃力 | 射程 | 移動力 |
| --- | --- | --- | --- | --- |
| 歩兵 | 5 | 2 | 1 | 1 |
| 騎兵 | 4 | 2 | 1 | 2 |
| 弓兵 | 3 | 1 | 3 | 1 |

学習・自動判断・オンライン対戦は含みません。1台のPCで両陣営の指示を設定し、同時に解決する検証用の対戦です。

## 構成

```text
src/
  main.ts                   # 画面の操作と実験状態の接続
  style.css                 # ページ全体のレイアウト
  ui/
    appShell.ts             # 共通ヘッダーとページ用サイドバー
    editorTabs.ts           # ユニット／マップの編集タブ
  core/
    board.ts                # 盤面・指示・同時移動・同時攻撃のルール
    board.test.ts           # ルールと境界条件のテスト
    initial-orders.test.ts  # 初期指示と目的地の検証
    order-reset.test.ts     # 指示の一括リセットと復元の検証
    combat.test.ts          # 陣営・戦闘能力・同時攻撃のテスト
    pathfinding.test.ts     # 迂回・到達不能・経路の再計算のテスト
    match.test.ts           # 優先権・壁・陣地・勝敗と終了のテスト
    scenario.ts             # 対戦用の初期ユニット・陣地・地形
    scenario.test.ts         # 対応する全マップサイズの初期配置
    session.ts              # 配置編集・開始配置・ターン履歴
    session.test.ts         # 開始配置とundoの復元テスト
    labels.ts               # ユニットの識別名
    unitTypes.ts            # 兵科・陣営・初期能力の定義
  game/
    createGame.ts           # Phaserの起動設定
    scenes/
      BoardScene.ts         # 盤面の描画とクリック入力
index.html                  # ブラウザ側の入口
vite.config.ts              # 開発サーバーとビルドの設定
tsconfig.json               # TypeScriptの設定
```

## 依存関係と確認

`package-lock.json`をコミットし、通常の環境準備には `npm ci` を使います。
依存パッケージを追加・更新するときは `npm install` を使い、
`package.json`と`package-lock.json`を合わせて更新してください。

GitHub Actionsでも `npm ci`、`npm test`、`npm run build` を実行します。
`node_modules/`、`dist/`、ローカル設定や検証用ファイルはGit管理に含めません。
